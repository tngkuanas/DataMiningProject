# Data Dictionary for Final ML-Ready Dataset (`final_ml_ready_dataset.csv`)

This document describes the schema for the final, ML-ready dataset. All features have been cleaned and converted to a purely numerical format.

## A. Target Variable

| Feature Name | Description                                                                 | Data Type |
| :----------- | :-------------------------------------------------------------------------- | :-------- |
| `is_fraud`   | Binary target variable: `1` if the transaction is fraudulent, `0` otherwise. | Integer   |

## B. Core Numerical Features

These features were either part of the original simulated data or were created programmatically.

| Feature Name                     | Description                                                                  | Data Type |
| :------------------------------- | :--------------------------------------------------------------------------- | :-------- |
| `transaction_amount`             | The monetary value of the transaction.                                       | Float     |
| `description_length`             | The character length of the original transaction description.                | Integer   |
| `transaction_frequency`          | The total number of transactions associated with the customer ID.            | Integer   |
| `hour_of_day`                    | The hour of the day (0-23) when the transaction occurred.                    | Integer   |
| `day_of_week`                    | The day of the week (0=Monday, 6=Sunday) when the transaction occurred.      | Integer   |

## C. LLM-Generated Numerical Features

These features were generated by the Gemini API based on semantic analysis.

| Feature Name                     | Description                                                                  | Data Type |
| :------------------------------- | :--------------------------------------------------------------------------- | :-------- |
| `consistency_score`              | An LLM-generated score (1-10) of how well the description aligns with the category. | Integer   |
| `entity_has_payment_instruments` | Binary flag (`1` or `0`) if the description mentions payment instruments.     | Integer   |
| `entity_has_gift_cards`          | Binary flag (`1` or `0`) if the description mentions gift cards.                | Integer   |
| `entity_has_crypto`              | Binary flag (`1` or `0`) if the description mentions cryptocurrency.          | Integer   |
| `entity_has_subscriptions`       | Binary flag (`1` or `0`) if the description mentions subscriptions.           | Integer   |
| `entity_has_refunds`             | Binary flag (`1` or `0`) if the description mentions refunds.                   | Integer   |
| `entity_has_P2P`                 | Binary flag (`1` or `0`) if the description mentions peer-to-peer transfers.    | Integer   |
| `entity_has_digital_goods`       | Binary flag (`1` or `0`) if the description mentions digital goods.             | Integer   |

## D. One-Hot Encoded Features

The original `merchant_category` and `transaction_country` text features were converted into multiple binary indicator columns. Each new column (e.g., `merchant_category_Electronics`, `transaction_country_US`) has a value of `1` if the transaction belongs to that category, and `0` otherwise.

## E. TF-IDF Features

The original `transaction_description` text feature was converted into 100 numerical features using `TfidfVectorizer`. Each column (e.g., `tfidf_urgent`, `tfidf_purchase`) represents the Term Frequency-Inverse Document Frequency score of a specific word, indicating its importance in the description relative to the entire dataset.
