# Data Dictionary for Final Preprocessed Dataset (`dataset_final.csv`)

This document describes the schema for the final, ML-ready `dataset_final.csv` file. The features have been cleaned, scaled, and encoded, ready for model training.

## A. Target Variable

| Feature Name | Description                                                                 | Data Type |
| :----------- | :-------------------------------------------------------------------------- | :-------- |
| `is_fraud`   | Binary target variable: `1` if the transaction is fraudulent, `0` otherwise. | Integer   |

## B. One-Hot Encoded Categorical Features

The following original features were converted into multiple binary indicator columns (one-hot encoding). Each new column (e.g., `transaction_type_transfer`) has a value of `1` if the original transaction belonged to that category, and `0` otherwise.

- `transaction_type`
- `merchant_category`
- `device_type`
- `payment_channel`
- `description_tone` (LLM-generated)
- `semantic_merchant_category` (LLM-generated)

## C. Standardized (Scaled) Numerical Features

These features have been transformed using a StandardScaler to have a mean of 0 and a standard deviation of 1.

| Feature Name                     | Original Description                                          | Data Type |
| :------------------------------- | :------------------------------------------------------------ | :-------- |
| `transaction_amount`             | The monetary value of the transaction.                        | Float     |
| `account_balance_before`         | Customer's account balance before the transaction.            | Float     |
| `account_balance_after`          | Customer's account balance after the transaction.             | Float     |
| `avg_transaction_amount_7d`      | Average transaction amount in the last 7 days.                | Float     |
| `time_since_last_transaction_hr` | Time elapsed (in hours) since the previous transaction.       | Float     |
| `account_age_days`               | Age of the customer's account in days.                        | Float     |
| `description_risk_score`         | LLM-generated risk score (1-10) based on description text.    | Float     |


## D. Passthrough Numerical Features

These features were kept in their original numerical format without scaling.

| Feature Name                  | Description                                                                  | Data Type |
| :---------------------------- | :--------------------------------------------------------------------------- | :-------- |
| `transaction_frequency_24h`   | Number of transactions by the customer in the last 24 hours.                 | Integer   |
| `num_failed_transactions_7d`  | Number of failed transactions by the customer in the last 7 days.            | Integer   |
| `transaction_hour`            | Hour of the day (0-23) when the transaction occurred.                        | Integer   |
| `is_weekend`                  | Binary flag: `1` if the transaction occurred on a weekend, `0` otherwise.    | Integer   |
| `user_risk_score`             | A simulated risk score (0-1) associated with the customer.                   | Float     |
| `num_devices_used`            | Number of unique device types the customer has used.                         | Integer   |
| `num_countries_used`          | Number of unique countries the customer has transacted from.                 | Integer   |
| `previous_fraud_count`        | Cumulative count of previous fraudulent transactions for the customer.       | Integer   |
| `kyc_verified`                | Binary flag: `1` if KYC is verified, `0` otherwise.                          | Integer   |

## E. Dropped Features

The following features from the original dataset were dropped during preprocessing as they are not suitable for direct use in the model:

- `transaction_id` (Identifier)
- `customer_id` (Identifier)
- `timestamp` (Datetime object)
- `transaction_description` (Raw text, used for feature engineering)
- `merchant_name` (Raw text, used for feature engineering)
- `customer_support_note` (Raw text, used for feature engineering)
- `location_match` (Dropped as per cleaning step)
