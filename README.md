# Fraud Detection Pipeline: Analysis and Comparison Report

## 1. Executive Summary

This report details the end-to-end development of a machine learning pipeline for fraud detection. The project involved synthesizing a realistic financial transaction dataset, engineering a diverse set of features using both programmatic methods and a Large Language Model (LLM), and evaluating a suite of six different classification models to identify the most effective solution.

The key finding is that gradient boosting models, specifically **XGBoost**, delivered the highest performance, achieving an F1-score of ~0.78 and a ROC AUC of ~0.97. This indicates a superior balance between correctly identifying fraudulent transactions (recall) and minimizing false alarms (precision). LLM-generated features, such as a `consistency_score` between transaction descriptions and merchant categories, proved to be highly predictive.

The final recommendation is the deployment of the XGBoost model due to its state-of-the-art performance. For cases requiring higher interpretability or a wider net for catching fraud at the cost of more false positives, the Random Forest or Logistic Regression models, respectively, serve as viable alternatives.

## 2. Project Objectives

The primary objectives of this project were to:
1.  **Synthesize a High-Quality Dataset:** Create a realistic, labeled dataset for financial fraud detection using the Gemini LLM to generate nuanced transaction details.
2.  **Engineer Advanced Features:** Enhance the dataset by creating both standard programmatic features (e.g., transaction frequency) and novel semantic features using an LLM (e.g., consistency scores, entity extraction).
3.  **Train and Evaluate Multiple Models:** Implement, train, and evaluate a diverse set of six machine learning models to establish a performance baseline and identify the most suitable algorithm for the task. The models evaluated were:
    *   Decision Tree
    *   Random Forest
    *   Logistic Regression
    *   K-Nearest Neighbors (KNN)
    *   XGBoost
    *   Neural Network (MLP)
4.  **Compare and Recommend:** Consolidate the performance metrics of all models into a single comparison file and provide actionable business insights and a final recommendation.
5.  **Document the Process:** Create a comprehensive report detailing every stage of the project, from data creation to final insights, including a full disclosure of AI usage.

## 3. Dataset Details

The project utilized a fully synthetic dataset, created and processed through a multi-stage pipeline.

*   **Raw Data Generation (`simple_llm_fraud_dataset.csv`):** The initial raw dataset of 2,619 transactions was generated by `llm_simple_dataset_simulation.py`. The Gemini API was prompted to create realistic but statistically-controlled fraudulent and legitimate transaction scenarios, including plausible descriptions, amounts, and categorical data. This approach ensured the presence of subtle, non-linear patterns for the models to learn.

*   **Feature-Engineered Dataset (`simple_llm_fraud_dataset_features.csv`):** The raw data was then enriched by `llm_feature_engineering.py`, which added several new programmatic and LLM-generated features.

*   **Final ML-Ready Dataset (`final_ml_ready_dataset.csv`):** The final step, handled by `final_cleaning_and_preparation.py`, involved cleaning the data (removing nulls) and converting all features into a purely numerical format via one-hot encoding for categorical data and TF-IDF for text.

## 4. Exploratory Data Analysis (EDA)

A brief analysis of the final, ML-ready dataset reveals the following key characteristics:

*   **Dataset Shape:** The final dataset contains **2,619 rows** and **160 columns** after all preprocessing. The high number of columns is a direct result of one-hot encoding categorical features and applying TF-IDF to the transaction descriptions.
*   **Fraud Rate:** The dataset has a fraud rate of approximately **8.13%**, which is a common level of class imbalance in fraud detection scenarios.
*   **Key Feature Statistics:**
    *   Average Transaction Amount: $184.28
    *   Average Description Length: 49 characters
    *   Average Transaction Frequency per Customer: 13.1 transactions
    *   LLM-generated Consistency Score (Avg): 4.96 (on a scale of 1-10)

## 5. Feature Engineering

The project employed a hybrid approach to feature engineering, combining standard techniques with novel LLM-based methods.

#### Programmatic Features (No LLM)
These features were created using the `pandas` library in the `llm_feature_engineering.py` and `final_cleaning_and_preparation.py` scripts:
*   **`description_length`**: The character length of the transaction description.
*   **`transaction_frequency`**: The total number of transactions associated with a given `customer_id`.
*   **`hour_of_day` & `day_of_week`**: Extracted from the `timestamp` to capture temporal patterns.

#### LLM-Generated Features
These advanced semantic features were generated by the `llm_feature_engineering.py` script using the Gemini API:
*   **`consistency_score`**: An integer score from 1-10 representing how semantically aligned the `transaction_description` is with the `merchant_category`. A low score indicates a potential anomaly.
*   **`entity_has_*` flags**: A set of binary flags indicating the presence of specific keywords or entities (e.g., `crypto`, `gift_cards`, `refunds`) in the transaction description.

## 7. Business Insights & Recommendations

Based on the model comparison, several key insights emerge:

*   **High-Performance Models Deliver Best ROI:** The superior performance of XGBoost and Random Forest justifies their use in a production environment. Their ability to balance precision and recall effectively means they can significantly reduce fraud losses without overwhelming fraud investigation teams with false positives.
*   **Precision vs. Recall Strategy:** The choice of model can be tailored to business needs.
    *   For a **"zero false positives"** strategy where any flagged transaction is almost certainly fraudulent, the KNN model could be used to trigger automated blocking rules, though it would miss many fraud cases.
    *   For a **"catch as much fraud as possible"** strategy, the Logistic Regression model, with its high recall, could serve as an initial filter to cast a wide net, even if it means more manual review.
*   **Feature Importance:** The high performance of all models indicates that the engineered features, particularly the LLM-generated `consistency_score` and entity flags, are providing strong predictive value. This validates the investment in advanced feature engineering.

**Final Recommendation:**

Deploy the **XGBoost model** as the primary fraud detection engine. It offers the best balance of performance (highest F1-score) and discriminatory power (highest ROC AUC), ensuring maximum fraud capture with an efficient rate of false positives. Its complexity is warranted by its state-of-the-art results on this complex, feature-rich dataset.

## 8. AI Usage Disclosure

In the interest of transparency, this project utilized the Google Gemini API in two key areas:

1.  **Synthetic Data Generation:** The initial raw dataset (`simple_llm_fraud_dataset.csv`) was entirely generated by prompting the `gemini-2.5-flash` model. The model was instructed to create a series of realistic fraudulent and legitimate transactions based on a set of probabilistic rules to ensure the data was realistic and contained non-linear patterns.

2.  **Semantic Feature Engineering:** The Gemini API (`gemini-2.5-flash` via `llm_feature_engineering.py`) was used to create advanced features from the raw data. This involved two tasks:
    *   Generating a **`consistency_score`** by evaluating the semantic relationship between a transaction's description and its merchant category.
    *   Extracting **entity flags** by analyzing the transaction description for specific keywords and patterns (e.g., 'crypto', 'gift card').

These steps were crucial for creating a high-quality dataset and a set of powerful predictive features that would be difficult to engineer using purely programmatic methods.
